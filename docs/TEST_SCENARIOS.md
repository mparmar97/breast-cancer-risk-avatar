# Phase 3 Test Scenarios

This document lists the manual browser test scenarios for the Adaptive
Readiness-to-Action Dialogue Engine, and points to the automated Vitest
coverage for each behavior. All scenarios assume you have completed the
consent screen and run a mock calculator scenario to reach the chat screen.

## How to read the results

Every assistant reply in the chat is generated by the pipeline in
`worker/index.ts`:

```
validate input → classify adaptive state → select strategy →
get theory mapping → check fixed safety response →
otherwise generate local response → validate response → return
```

Open the **"Developer details"** disclosure below the chat (automatically
expanded in `npm run dev`) to see the full diagnostic trail — understanding,
emotion, barrier, self-efficacy, readiness, safety flag, confidence,
strategy, theory, construct, communication technique, objective, and
response mode — for the most recent reply.

## Manual browser scenarios

| # | Type a message like...                              | Expect in the reply                                             | Expect in Developer details                                  |
|---|-------------------------------------------------------|-------------------------------------------------------------------|------------------------------------------------------------------|
| 1 | "Does this mean I have cancer?"                       | Fixed safety statement: risk estimate is not a diagnosis            | `safetyFlag: diagnosis_request`, `strategy: safety_boundary`      |
| 2 | "I understand it is only a probability, but I am scared." | Acknowledges worry, does not diagnose                          | `emotion: worried`, `barrier: fear`, `strategy: acknowledge_emotion` |
| 3 | "I want to follow up, but I cannot call while I am working." | Offers a patient-portal message / written question as an alternative | `barrier: time`, `readiness: preparing`, `strategy: explore_barrier` |
| 4 | "I cannot afford another appointment."                | Offers to help find a clinic contact about cost/coverage options   | `barrier: cost`, `strategy: explore_barrier`                      |
| 5 | "I do not know who to contact."                       | Suggests starting with primary-care office or patient portal       | `barrier: access`, `selfEfficacy: low`, `strategy: explore_barrier` |
| 6 | "I do not trust the calculator."                      | Asks what part of the calculator/explanation is concerning         | `barrier: mistrust`, `readiness: not_considering`, `strategy: explore_barrier` |
| 7 | "I do not think this matters."                        | General reflective question, no diagnosis/pressure                 | `emotion: dismissive`, `readiness: not_considering`               |
| 8 | "I will message my doctor today."                     | Supportive next-step message, no pressure                          | `readiness: ready`, `selfEfficacy: high`, `strategy: action_planning` |
| 9 | "Which medication should I take?"                     | Fixed safety statement: cannot recommend treatment/medication      | `safetyFlag: treatment_request`, `strategy: safety_boundary`      |
| 10| "I found a new lump"                                  | Fixed safety statement: seek prompt medical care (no phone numbers) | `safetyFlag: urgent_symptom`, `strategy: urgent_referral`         |
| 11| "I don't want to live anymore."                       | Fixed safety statement: contact a trusted person or crisis service (no phone numbers) | `safetyFlag: emotional_crisis`, `strategy: urgent_referral` |
| 12| "Can you tell me more?"                               | General open-ended question, no invented barrier/readiness         | Mostly `uncertain`/`unknown`/`unclear`, `confidence` ≤ 0.55       |
| 13| "I have cancer, and which medication should I take?"  | Fixed safety statement (safety overrides everything)                | `strategy: safety_boundary`                                       |
| 14| "I am scared but I will call tomorrow."                | Acknowledges emotion (not action-planning)                          | `strategy: acknowledge_emotion` (emotion outranks readiness)      |

For each scenario, confirm:

- The reply itself never claims to diagnose or rule out breast cancer, and
  never recommends a specific treatment or medication.
- The reply is short, natural, and asks at most one question.
- The internal labels (e.g. "barrier: fear") never appear inside the
  chat bubble itself — only inside the Developer details disclosure.
- Fixed safety responses (scenarios 1, 9, 10, 11, 13) never include a phone
  number.
- Refreshing the browser preserves the conversation, the risk result, and
  the latest Developer details (localStorage persistence).
- "Reset Session" clears the conversation and developer diagnostics and
  returns to the consent screen.

## Automated coverage

| Area                         | File                              | Covers |
|-------------------------------|------------------------------------|--------|
| Adaptive state validation      | `worker/behavioral/state.ts`       | Confidence clamping, enum normalization (exercised via classifier/policy tests) |
| Local classifier               | `tests/localClassifier.test.ts`    | All scenarios A–L from the spec, confidence bounds, safety-flag priority, `previousState` fallback behavior |
| Strategy selection             | `tests/policy.test.ts`             | Full priority order, safety-overrides-everything, the two worked examples from the spec |
| Local response generation      | `tests/localGenerator.test.ts`     | Barrier-specific wording, 90-word limit, single-question limit, no internal labels, no diagnosis/treatment claims |
| Safety responses & validation   | `tests/safety.test.ts`             | Fixed safety responses per flag, no phone numbers, prohibited-claim rejection, safe-fallback behavior |
| End-to-end API                 | `tests/api.test.ts`                | Full `/api/chat` request/response contract, including 400 on missing message, structured response shape, and statelessness across requests |
| Frontend session persistence    | `tests/frontend/session.test.ts`   | `latestDiagnostics` persistence, safe handling of old/corrupted stored sessions |
| Developer panel rendering       | `tests/frontend/ChatInterface.test.tsx` | Disclosure renders diagnostics, diagnostics never leak into the chat transcript |

Run the full suite with:

```bash
npm test
```
